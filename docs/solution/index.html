Kickstream solution overview and scope

Kickstream is live-streaming software for football. A host creates a broadcast, composes scenes in the studio, and goes live to YouTube, X, Facebook and Twitch at once. What the program shows comes from a match event stream turned into live intelligence, AI narratives and recaps. Seven analyst agents, working in three teams, read the match as it happens; a unified analytics dashboard joins the match, the agents, the audience and the broadcasts on one page; auto live runs a channel by itself with a spoken commentator in twenty languages. Agents then cut the recording’s best moments into vertical reels.

The match is synthetic by default: a seeded simulator plays Northbridge FC against Harbour City, two fictional clubs, so every insight can be produced and replayed without licensed data. This set answers the challenge The Synthetic Match Insights Engine for Premier League Studio. Edition: 20 October 2026.

What changed in this edition

  • Teams of analyst agents. The seven match agents work as the Match Reading, Forecast and Story teams. /match is called Analyst teams.
  • Unified analytics. /dashboard brings the match, the teams’ work, the players, the audience, the broadcasts and auto live onto one live page.
  • Agent tools. Each agent takes custom instructions, up to three connectors of the operator’s own, and a chat.
  • Auto live in twenty languages, each with matching Azure neural voices.
  • Studio. One commentary for the program, nine background plates, element delete, a large solo camera frame, and a goal celebration.
  • Operations. Deploy from GitHub with OIDC, match logs in Cosmos DB, and narration through a Microsoft Foundry project.

This set describes the software in this repository: the web studio, the Python pipeline, and the Azure resources deploy/terraform actually creates. It is the solution description an architect or operator can build from. It is not a store listing.

Kickstream does not implement Microsoft Marketplace SaaS fulfillment, an Entra purchase landing page, or a live Partner Center offer. The Entra application in deploy/terraform/auth.tf is a single-tenant studio gate for the deployer, not a buyer sign-in.

Studio

Home, broadcast, and studio. Scenes, banners, guests, and one Go live control.

Match pipeline

Ingest, interpret, explain, render, and personalize, plus seven agents in three analyst teams.

Azure deploy

One Container App, Cosmos match log, Communication Services, Speech, Files, Registry. Deployed from GitHub.

Local run

Python 3.13 and Node 24. A seeded 90-minute match plays in about three minutes.

What is in scope

  • The web app in apps/web: home (/), a broadcast (/broadcasts/{id}), that broadcast’s studio, /studio, Analyst teams (/match), unified analytics (/dashboard), a guest page (/guest/{secret}), and auto live (/live).
  • The pipeline in services/pipeline: FastAPI on port 8000, match simulation or a chosen source, analytics, narration, overlay, gateway (Server-Sent Events and WebSockets), output to platforms, fans, broadcasts, reels, and Ask Copilot.
  • The deployment in deploy/: Terraform for the resource group, deploy.ps1 / deploy.sh to build the image and apply it, and .github/workflows/ to test and deploy from GitHub.
  • Languages on the match surface: English, Spanish, and Hindi. Auto live speaks twenty. Commentary modes: Fan and Analyst.

What is out of scope

  • A transactable Marketplace offer, fulfillment webhooks, metering, or a purchase landing page that resolves a Marketplace token.
  • StatsBomb Open Data inside a paid offer. That source is non-commercial and is off unless real_sources is set. See Integrations.
  • A video detector. The synthetic match, or a JSON Lines file named by KICKSTREAM_DETECTOR_FILE, stands in for detections. There is no video understanding in the pipeline.
  • Taking money from fans. Superchats are displayed. Payment stays on the platform the fan already used.
